## 1. 먼저 전체를 설계하고, 실제 집필로 검증한다

현재 66강 자료 배정표는 제목과 관련 자료 후보를 연결한 표다. 강의 사이의 선행 지식·결론·결과물이 이어지는 전체 논리 개요는 별도로 작성해야 한다.

순서: 전체 과정의 도착점 → 챕터별 변화 → 66강 연결 개요 → 대표 강의의 상세 논증 및 대본 시범 → 전체 개요 보정 → 챕터별 상세 개요 → 강별 집필 → 앞뒤 강의 연결 검토.

전체 개요 단계에서 66강의 모든 대사를 쓰지 않는다. 다만 각 강의의 입력, 해결할 질문, 핵심 결론, 그 결론에 필요한 이유, 결과물, 다음 강의가 필요한 이유는 빠짐없이 적는다. 기존 시트 제목과 순서를 유지하며 선행 지식 충돌이 발견되면 충돌과 수정안을 기록한다.

한 강을 집필할 때 해당 강과 앞뒤 강의 개요를 함께 펼친다. 이미 가르친 개념은 필요한 만큼 회상시키고, 뒤에서 가르칠 방법은 현재 판단에 필요한 범위까지만 소개한다. 새로운 개념을 넣으면 최초 설명 강의와 뒤에서 사용하는 강의도 함께 갱신한다.

## 2. 원문에서 강의로 옮기는 중간 단계

책의 전개 순서와 강의의 전개 순서는 다를 수 있다. 다음 경로로 추적한다.

원문 위치 → 원문이 주장하는 것과 성립 조건 → 우리 강의에서 가르칠 판단 → 그 판단에 필요한 근거·설명 → 문단 → 말로 읽을 문장.

각 주장에 C001 같은 ID를 주고 아래를 기록한다.

- 원천 ID, 파일, 장·페이지, 문단 첫 구절: 다시 같은 대목을 찾는 위치.
- 원문의 주장, 이유, 전제, 예외: 저자가 말한 범위.
- 우리 강의의 주장: 그대로 설명하는지, 여러 자료를 종합하는지, 다른 업종으로 적용하는지.
- 변환 이유와 추가 전제: 서로 다른 자료 사이에서 우리가 새로 연결한 추론.
- 강의 위치: 어떤 강의·문단·문장에서 쓰는지.
- 검증 상태: 원문 확인 / 적용 추론 검토 / 근거 부족.

말투나 연결 질문마다 책의 한 문장을 억지로 붙이지 않는다. 실제 주장·수치·사례가 들어간 문장은 근거 카드로 추적하고, 질문·회상·전환은 어떤 주장 사이를 왜 연결하는지 추적한다. 여러 출처가 같은 주장을 반복해도 독립적인 검증으로 세지 않는다.

원문의 업종·구매 주기·제공 방식과 우리 적용이 다르면 조건을 적는다. 원문만으로 결론이 안 나오면 적용 가설로 표현하거나 결론 범위를 줄인다. 중간 추론을 생략한 채 출처 이름만 붙이지 않는다.

## 4. 완벽한 문장 대응이 안 될 때

| 방식 | 적용 상황 | 남길 기록 |

| 문장 대응 | 문장 기능과 전제가 우리 내용에서도 성립 | BPT 문장 ID ↔ 새 문장 ID, 연결 이유 |
| 문단 기능 대응 | 설명 길이나 사례 수가 달라 일대일 대응이 부자연스러움 | 원문 구간 ↔ 새 문단, 보존한 논리 관계, 추가·축약 이유 |

| 독립 설계 | 기존 패턴도 맞지 않음 | 필요한 새 연결과 이유, BPT 미대응 표시 |

문장 수를 맞추기 위해 근거를 빼거나 불필요한 말을 추가하지 않는다. 문단 기능 대응 이하로 바뀐 구간은 검토 기록과 사용자 보고에서 밝힌다. 확인한 패턴 없이 일반적인 글쓰기 규칙을 BPT 기준이라고 부르지 않는다.

## 5. 문장·문단·강의 사이의 연결 검토

아래 항목은 이번 사용자 요구에 맞춘 검토 기준이다. BPT의 확정된 원래 규칙이라는 뜻은 아니다.

### 문장 사이

- 앞 문장을 받아 설명·원인·조건·대조·근거·예시·결론 중 무엇을 더하는가?
- 결론에 필요한 중간 전제가 빠지지 않았는가?
- 예시는 어떤 주장까지 보여주는가? 한 사례로 모든 업종을 단정하지 않는가?
- 질문에 답했는가? 뒤에서 답한다면 어디서 회수하는가?
- 새 용어는 이해할 준비가 된 뒤 등장하는가?

### 문단 사이

각 문단에 '들어올 때의 생각 → 해결할 질문 → 주장 → 근거와 설명 → 나갈 때의 생각 → 다음에 남는 질문'을 쓴다. 모든 문단을 동일한 길이·순서로 쓰라는 뜻은 아니다.

다음 문단은 앞 문단에서 남은 질문을 해결하거나, 이미 확인한 결론을 다음 판단에 적용해야 한다. '그리고·그래서'만으로 연결을 대신하지 않는다. 문단 순서를 바꿔도 의미가 같다면 현재 순서가 필요한 이유를 다시 검토한다. 이 검사는 진단용이며 병렬 사례까지 억지로 인과관계로 만들지는 않는다.

### 강의 사이

이전 강의 결과물 → 이번 강의에서 사용하는 지점 → 이번에 새로 가능한 판단 → 다음 강의가 해결할 남은 문제를 적는다. 다음 편 예고만으로 연결 완료로 보지 않는다.

### 설명 예시 — 실제 BPT 대응이나 검증된 사례가 아닌 논리 시연

1. 연락처가 있어도 아직 구매하지 않은 고객이 있다.
2. 연락처만으로는 그 고객이 구매를 미룬 이유를 알 수 없다.
3. 그러므로 다음 메시지를 정하려면 고객이 무엇을 더 알아야 하는지 판단할 정보가 필요하다.
4. 예를 들어 가격 안내를 요청한 고객과 사용법을 질문한 고객은 필요한 정보가 다를 수 있다.
5. 이 차이를 확인할 질문이나 행동 기록을 정하고, 그 정보에 따라 메시지를 나누어 보자.

'DB가 필요하다 → CRM을 하자' 사이에 이유 파악과 정보 수집이라는 전제를 보충한 예다. 실제 강의에는 관련 원문 근거와 적용 조건을 추가한다.

2. **BPT 설계 기준 카드:** 확인 가능한 구간에서 관찰한 패턴을 기록한다. 전사 불명확 부분은 확정하지 않는다.
3. **대표 강의 시범:** 문단 개요→주장 카드→대응표→대본으로 내려가 실제 연결을 검토한다.

## 7. 개요의 깊이와 자료 확인 순서 — 추가 사용자 지시

개요 작성 전에 설계자 4권·100M 3권·구피디 21편·콰디 11편 전체를 조사 대상으로 놓고, 각 자료의 본문 확인 범위와 미확인 범위를 기록한다. 기존 핵심 요약과 자료 후보 배정만으로 전체 본문을 검토했다고 표시하지 않는다. 모든 자료의 핵심 주장·적용 조건을 검토하고 강의별 채택·보류 이유를 남긴 뒤 개요를 구성한다. 제목만 보고 자료를 배정하거나, 먼저 만든 주장에 맞는 구절만 사후에 붙이지 않는다.

자료에서 핵심 주장·이유·조건·사례를 추출 → 강의 목적과 대조 → 서로 보완하거나 충돌하는 소스 비교 → 필요한 원리·근거 선택 → 강의의 논증 순서 설계. 관련 자료는 같은 강의 안에서 조합하되 모든 소스를 매 강에 강제로 넣지 않는다.

개요는 기본 논리 구조를 읽고 검토할 수 있는 완전한 문장 수준으로 작성한다. 키워드와 주제 목록만으로 완료하지 않는다. 문단별 대사와 말투를 완성하는 단계와는 구분한다.

각 강의에 최소한 다음을 적는다.

1. 이전 강의에서 확보한 이해·결과물과 이번에 남은 문제.
2. 수강생의 기존 생각 또는 현재 행동, 그리고 그 한계.
3. 이번 강의가 답할 핵심 질문.
4. 결론에 필요한 주장들의 순서. 각 주장마다 이유·원문 위치·조건·중간 추론을 붙인다.
5. 납득을 도울 사례와 그 사례가 입증하는 범위, 예상 반론과 답변.
6. 따라서 도달하는 결론과 실제로 바뀌는 판단·행동·결과물.
7. 이 결론만으로 아직 해결되지 않는 문제와 다음 강의가 필요한 이유.
8. 대응할 BPT 구간·패턴과 연결 원리, 대응 불가 부분 및 대체 이유. 미확정이면 그대로 표시.

개요 검토자는 '왜 이 주장이 다음 주장으로 이어지는가'와 '어느 자료로 말할 수 있는가'를 대본 없이 확인할 수 있어야 한다. 자료가 부족하면 필요한 근거를 명시하며, 추측으로 논증을 완성하지 않는다.

이 항목은 사용자가 말한 기본 논리 구조의 깊이를 구체화한 작업안이다. 이어지는 사용자 설명이 있으면 그 설명을 우선 반영한다.
