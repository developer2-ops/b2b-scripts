# 챕터 개요 작성 규칙

## 1. 적용과 역할

- 개요 관련 답변·수정 전에 이 문서와 [대본 제작 규칙](05_대본제작규칙.md) 전체를 읽고, 해당 챕터 최신 파일과 사용자 교정을 확인한다. 두 문서는 함께 적용하며 사용자 최신 지시를 우선한다.
- 기본은 사용자와 구체적인 개요·논리 구조를 함께 정하는 단계다. 2026-09-20 요청에 따라 4강은 검토용 대본 초안을 작성하고 5강은 지정 내용을 먼저 저장한다. 다른 강의까지 집필·승인 범위를 확대하지 않는다. 직원은 이후 관련 자료를 전부 읽고 설명·근거·사례를 보완한다. 사용자가 최종 논리와 문장을 수정해 그대로 읽을 촬영 대본을 만든다.
- 개요에는 강의에서 할 말, 전개 순서, 문장·문단 사이의 논리, 필요한 근거의 위치와 각 강의의 범위가 드러나야 한다. 주제 목록만 만들거나 최종 촬영 대본을 임의로 완성하지 않는다.

## 2. 사용자 내용과 말투

- 대화·개요·대본에서는 회사의 가치를 가리키는 표현을 ‘기업가치’로 통일하고 ‘회사의 지분가치’라는 표현은 쓰지 않는다. 용어 통일과 별개로 계산에 쓰는 순이익·영업이익 및 배수의 기준은 정확하게 유지한다.

- 사용자에게 하는 대화는 자연스러운 존댓말로 쓴다. 강의 문장도 기본은 존댓말이지만, 사용자가 확정 1강의 말투와 설명 방식을 따르라고 지정한 CH00 개요는 그 본문의 문체·호흡을 따른다. 기존 사용자 직접 작성 부분은 요청 없이 일괄 변경하지 않는다. 확정 1강을 참고할 때 용어 정의를 항목별로 나열하는 교과서식 설명으로 바꾸지 말고, 앞말에서 생기는 질문·오해를 받아 이유와 예시로 이어가는 문단을 쓴다. ‘그럼’, ‘근데’ 같은 접속어만 흉내 내지 않고 내용의 연결도 맞춘다.

- 사용자가 관찰·추정으로 말한 내용을 ‘나는 ~라고 정의한다/말한다’처럼 화자의 개인 선언으로 바꾸지 않는다. ‘~인 것 같다’ 등 원래 표현의 강도와 태도를 유지한다.

- 고객 관계를 설명할 때 ‘뺏고 빼앗는다’, ‘경쟁’ 같은 대립적인 표현보다 ‘고객의 선택을 받는다’, ‘우리를 선택할 이유를 만든다’처럼 긍정적인 표현을 우선 검토한다. 단어만 순화하지 말고 고객에게 다른 선택지가 있고 요구와 선택 이유가 달라질 수 있다는 중간 논리를 설명한다.

- 사용자가 MD에서 직접 수정한 내용·삭제·순서·표현·서식을 유지한다. 편집 직전에 디스크의 최신 파일을 다시 읽고 요청 범위만 최소 수정한다. 이전 답변·백업·기억 속 버전으로 덮어쓰거나 사용자가 지운 내용을 임의로 복원하지 않는다. 저장 전 파일이 달라졌으면 최신본을 다시 읽어 사용자 변경을 보존한 뒤 적용하고, 수정 후 요청 범위 밖 내용이 바뀌지 않았는지 확인한다. 사용자가 추가만 요청한 경우 기존 문장·번호·순서·서식을 바꾸지 않고, 앞뒤 논리에 맞는 위치에 새 내용만 삽입한다. 답변에는 추가 위치와 내용을 명시한다.

- 원본을 보존한다. 적당히 요약할 수 있지만 주장·질문·반론·조건·사례·감정을 빠뜨리지 않는다. 오타·띄어쓰기와 `&#x20;` 같은 불필요한 문자를 정리한다.
- 본문은 사용자의 말투로 쓴다. ‘연결한다’, ‘맥락에 들어간다’, ‘설명해야 한다’ 같은 기획자의 해설로 바꾸지 않는다.
- 사용자에게 없는 정의·해석·처방을 원래 말씀처럼 섞지 않는다. 새로운 연결이나 표현은 제안임을 구분하고 함께 논의한다.
- ‘팬’은 쓰지 않는다. 고객·시청자·구독자는 실제 관계에 맞게 구분한다.

## 3. 대상과 논리

- 사용자가 핵심을 한 문장으로 정리한 뒤 나눠 설명하고 챕터에 연결하라고 요청하면, 그 문장의 요소를 실제 판단·실행으로 풀어 같은 요소가 챕터별 학습 내용과 이어지게 쓴다. 별개의 주제 목록이나 챕터명 나열로 대신하지 않는다. 해당 강의에 지정한 전개를 모든 강의의 고정 형식으로 확대하지 않는다.

- 매 강의의 맨 앞에는 이전 강의 복습을, 맨 마지막에는 그날 배운 내용 복습을 둔다. 복습을 통합해서 정리하라는 요청은 복습 안내나 강의 번호를 전부 없애라는 뜻이 아니다. 먼저 무엇을 복습하고 왜 정리하는지 밝힌 뒤, 각 강의가 목표에 어떤 설명을 더했는지 한 흐름으로 연결한다. 복습에 개인 스토리를 보완할 때는 복습을 중심에 두고, 강사가 왜 그 내용을 강조하는지 경험과 신뢰가 드러나는 짧은 장면을 넣는다. 스토리를 위해 별도의 주장이나 긴 사례 강의로 바꾸지 않는다. 짧은 개인 경험이라도 지금 복습하는 논점을 직접 뒷받침해야 한다. 관련 없는 다른 문제로 주제를 옮기는 사례를 억지로 넣지 않는다. 실패·후회 경험을 붙일 때는 당시의 어떤 판단이 앞에서 설명한 기준을 놓쳤는지와 그 결과를 분명히 연결한다. 사례의 표면적인 행동만 지적해 다른 교훈으로 바꾸지 않는다. 복습에서는 앞 강의 최신 본문에서 실제 사용한 핵심 단어·용어를 그대로 쓰고, 쉬운 설명을 덧붙이더라도 다른 표현으로 대체해 배운 개념과의 연결을 끊지 않는다. 도입에서도 “회사에 쌓이는 것”처럼 대상을 흐리게 뭉뚱그리지 말고, 필요한 개념이나 오늘 설명할 판단을 구체적으로 말한다. 특히 4강은 1~3강의 목표와 내용을 총정리하겠다는 안내→영업이익 목표→이익·자산, 고객 가치·비용, 선택 방식의 변화→왜 대표의 마케팅적 판단이 필요한지→다음 달과 장기 매출 투자 비교→매출·지출 숫자→지속 개선으로 설명한다. “몇 강과 이어서 생각하자”라는 말만 반복하며 실제 논리 연결을 대신하지 않는다. 첫 강의에는 이전 강의가 없으므로 해당 복습을 만들지 않는다. 매 강의 AI 복습과 제공 프로그램을 이용하도록 안내하고, 챕터가 끝나면 챕터별 복습 강의를 둔다. 테스트 통과 후 다음 강의로 넘어가는 운영 방식은 5강에서 안내한다. 구체적인 테스트 기준·프로그램 기능은 확인 없이 만들지 않는다. 기존 강의 전체 수정은 별도 요청 범위에 따라 진행한다.

- 모든 강의의 서론과 마지막에는 이 강의를 배우는 이유, 수강생의 사업에 어떤 도움이 되는지, 전체 커리큘럼에서 왜 이 내용을 이 위치에 넣었는지를 해당 강의의 구체적인 문제와 연결해 설명한다. 본문의 학습 동기부여는 문단 수에 맞춰 의무적으로 넣지 않는다. 기존의 “3~4문단마다” 삽입 기준은 적용하지 않으며, 사례에서 적용할 판단이 드러나거나 다음 내용을 배울 이유가 자연스럽게 생기는 기회에만 연결한다. “이걸 배워 회사를 키우자”, “국내외 사례를 계속 보자” 같은 문구를 설명 중간에 기계적으로 끼워 넣지 않는다. 바로 앞의 내용만으로 도움과 이유가 드러나면 별도의 동기부여 문장을 추가하지 않는다. 서론·마무리에서도 본문의 구체적인 내용에서 학습 가치를 이어가며 같은 주장·예시를 반복하지 않는다. 새 지시를 참고해 일부 보완하라는 요청은 기존 내용을 새 지시 중심으로 전면 재작성하라는 뜻이 아니다. 맞는 설명과 필요한 예시는 유지하고 관련 있는 부분만 반영한다. 길이를 줄일 때도 핵심 차이를 설명하는 내용을 통째로 덜어내지 않고 반복과 불필요한 표현부터 정리한다.

- 국내외 사례와 트렌드를 꾸준히 추적하고 참고할 사례를 쌓는 이유도 해당 사례·설명에서 자연스럽게 이어질 때 다룬다. 모든 사례 뒤에 같은 권유를 붙이지 않는다. “누가 얼마 벌었다”, “어느 회사가 상장했다”에서 끝내지 않고, 어떤 고객·시장 변화를 읽었고 상품·설명·채널·구매 과정을 어떻게 바꿨으며 그중 우리 회사에 무엇을 적용할 수 있는지 살핀다. 사례에서 확인한 실행과 결과, 강의의 적용 해석을 구분하고 성과 전체를 한 채널이나 방법 덕분으로 단정하지 않는다. 수강생이 강의 이후에도 국내와 해외의 사례를 계속 보며 변화에 대응하고 회사를 키울 판단을 기르도록 연결한다.

- 원가와 고객 가치를 연결할 때 재료·품질 문제로만 좁히지 않는다. 원가를 더 쓰는 것 외에도 제안의 구성과 가치 전달이 고객의 인지 가치에 영향을 줄 수 있음을 구분한다. 인지 가치 상승을 원가 상승과 같은 뜻으로 쓰지 않는다.

- 사용자가 작성한 지점 다음을 이어 달라고 하면, 앞서 제시한 내용·방향과 최신 본문을 기준으로 다음 번호부터 실제 개요를 이어 쓴다. 이미 정한 방향을 다시 제안하거나 읽은 내용 요약만으로 대신하지 않는다. 사용자 작성 구간은 보존한다.

- 기업가치·회계 계산을 설명할 때는 핵심 식을 먼저 제시하고, 주장 이해에 필요한 용어를 쉬운 말로 하나씩 풀어 설명한다. 용어 설명을 늘려 핵심 흐름을 어렵게 만들지 않는다. PER·이익·판매비와관리비의 의미를 실제 사업의 판단과 연결하며, 마케팅 지표 분해로 성급히 넘어가지 않는다. 강의 목표와 커리큘럼을 설명할 때도 영업이익 개선 목표→매출·원가·판관비에서 바꿀 것→필요한 고객 행동 변화→구체적인 실행과 해당 챕터 순서로 내려간다. 이때 앞 강의에서 사용한 공식과 설명을 출발점으로 삼고, 매출·매출원가·판관비 각각의 개선이 고객의 가치 인식·선택·구매 과정과 어떻게 연결되는지 차례로 풀어 현재 강의를 배운 이유로 이어간다. 고객 수·구매 횟수 같은 새 지표 분해로 기존 설명을 건너뛰지 않는다. 여러 핵심어를 한 문장에 나열하는 것으로 목표와 실행 사이의 논리를 대신하지 않는다. 전체 평가식에서 구성 항목으로 내려가는 탑다운 순서를 지키고, 용어를 풀 때 같은 사업 예시와 숫자를 이어 붙여 이해를 돕는다. 사용자가 요청한 핵심 용어 두 개 정도는 유지하되 용어 수 자체를 목적 삼지 않는다. 아직 설명하지 않은 용어나 뒤 챕터의 개념을 수강생이 이미 안다는 전제로 쓰지 않는다. 처음에는 익숙한 말로 무엇을 뜻하고 어떤 일을 하는지 설명하며, 뒤 내용을 예고할 때도 개념 이름만 부르지 말고 무엇을 배우는지 풀어 말한다.

- 같은 반론·고민과 답을 여러 항목에서 반복하지 않는다. 중복 정리 요청 시 해당 구간을 한 번의 문제 제기→이유→예시→다음 판단으로 통합하되, 서로 다른 내용과 사용자 감정·조건은 보존한다. 접속어만 바꿔 반복을 남기지 않는다. 앞 문단의 결론을 다음 문단 도입에서 다시 설명하지 말고, 그 결론을 바탕으로 필요한 다음 판단으로 나아간다.

- 문장을 수정할 때는 반드시 앞 문장과 뒤 문장을 함께 읽고, 문단을 수정할 때는 반드시 앞 문단과 뒤 문단 전체를 함께 읽는다. 선택된 문장·문단만 따로 보고 고치지 않는다. 수정 전에 앞 내용에서 무엇을 받아야 하고 뒤 내용으로 무엇을 이어줘야 하는지 확인한 뒤, 양쪽이 자연스럽게 연결되도록 수정한다. 수정 후에도 앞뒤 문장·문단을 이어서 다시 읽어 연결을 검증한다. 이와 함께 수정 전후에 해당 섹션 전체를 읽고, 같은 주장·설명·예시·결론을 표현만 바꿔 반복하지 않는지 확인한다. 두 점검을 모두 마친 뒤에만 수정 완료로 보고한다. 한 항목의 연결을 고칠 때 앞 문장의 끝말만 받거나 연결 문장을 덧붙이는 것으로 끝내지 않는다. 여러 항목이 이어지지 않는다는 교정에는 각 항목을 따로 매끄럽게 고치지 말고, 앞 항목의 주장이 왜 다음 설명을 필요로 하는지 전체 전개에서 빠진 이유를 보완한다. 반복·역행·성급한 해결책 제시가 있으면 필요한 구간의 순서를 정리한다. 이동한 내용은 누락하지 않고, 해당 강의의 번호 중복·누락도 함께 확인한다. 사례 뒤에 “그럼 우리 사업에서는 뭘 봐야 할까” 같은 포괄적인 질문으로 흐름을 다시 시작하지 않는다. 앞에서 설명한 구체적인 내용에서 다음 판단이 필요한 이유를 이어 쓴다. 두 개념의 차이는 앞 문장의 흐름 안에서 설명한다. “넘어갔다·바뀌었다” 뒤에는 무엇에서 무엇으로 달라졌는지 풀고, “A는 ~다, B는 ~다”라는 독립적인 정의 나열로 끊지 않는다. 차이와 쉬운 예시를 먼저 말하고, “물론 ~의 일부다” 같은 관계·단서 설명은 그 뒤에 둔다. 새 서비스나 수익 방식을 소개할 때는 앞에서 설명한 행동이 어떻게 그 구조로 이어지는지 먼저 풀고 서비스명을 붙인다. “이것도 봐야 한다”, “먼저 ~를 보면 된다”는 진행 안내만으로 연결을 대신하지 않는다. 왜 다음 내용이 필요한지 앞의 주장과 이어지는 이유·근거를 직접 설명한다. “그 답을 찾기 위해”처럼 답을 예고하면 뒤 내용이 그 질문에 실제로 답하는지 확인한다. 복습이 먼저 필요한 경우 질문을 답변 직전으로 옮겨, 복습과 실행 답변의 역할을 구분한다.

- 번호가 바뀌어도 앞 항목의 말을 받아 이어지는 개요로 쓴다. 예: ‘생각이 바뀌었다’ 다음에는 ‘생각이 어떻게 바뀌었냐면’으로 답한다. 접속어만 붙이지 말고 앞에서 생긴 질문에 답하는지, 다음 이야기의 이유가 충분한지 검토한다. 빠진 이유는 사용자와 논의하며 임의의 주장으로 채우지 않는다. 시대나 환경의 변화를 설명할 때는 다음 단계로 넘어갈 수 있었던 배경과 고객 행동의 변화를 풀고, 그 핵심을 강의 앞에서 알려주겠다고 약속한 판단과 연결한다. 서비스 등장 순서만 나열하거나 기능의 존재를 시대 전환의 유일한 원인으로 단정하지 않는다. 시대 구분은 “다음 세대”로만 부르지 않고 “1세대, 2세대”처럼 번호와 이름을 함께 말한다. 시대 명칭은 전환의 도입부에서 강사가 직접 말하되, 앞 시대의 끝과 다음 시대의 시작 사이에 환경 변화와 고객 행동의 연결을 먼저 설명한다. “이제 다음 시대로 넘어간다”는 선언만으로 전환하지 않는다. 본문 중간에만 이름을 두어 전환이 묻히지 않게 하며, 같은 시대의 보충 설명이면 그 시대 안의 이야기임을 밝힌다. 별도 소제목을 붙이는 것으로 대신하지 않는다. 시대 전환은 이전 방식에서 고객이 어떻게 행동했고 다음 환경에서 무엇이 달라졌는지 같은 상황의 전후로 비교한다. 성공·쇠퇴 사례를 요청받으면 실제 회사의 대응과 확인한 결과를 넣되, 변화와 성과의 인과를 단정하거나 시장 철수·서비스 중단을 회사 전체의 소멸로 바꾸지 않는다. 다른 챕터로 마무리를 연결할 때는 실제 최신 개요의 번호와 내용을 확인하고, 앞서 설명한 문제를 해결하기 위해 그 챕터에 무엇을 넣었는지 이유까지 본문에서 풀어준다. 챕터명 나열이나 다음 강의 예고만으로 대신하지 않는다. 다만 사용자가 구체적인 분해·적용·챕터 연결을 다음 강의에서 다루겠다고 범위를 정하면, 현재 강의에서는 핵심 결론과 다음에 무엇을 배울지까지만 말하고 상세 설명은 앞당겨 넣지 않는다. 세대별 변화는 이전 방식의 소멸로 설명하지 않고, 현재 남아 있는 역할과 달라진 사용 방식을 함께 보여준다. 결론은 유행하는 채널의 선택 자체보다 방법의 원리와 회사에 필요한 역할을 판단하는 것으로 연결한다.

- 예비창업자·초기·기존 사업자, 1인기업·소수 인원·조직, 업종과 원하는 규모 등 해당 주장에 영향을 주는 경우를 검토한다. 회사 규모를 비교할 때는 같은 수단을 쓰는 방법과 그 실행을 구성하는 방식을 구분한다. 현재 규모만으로 성장 가능성을 정하지 않고, 방법의 이해·적용과 직접 실행·팀 구성·목표 규모의 차이를 설명한다.
- 경우를 나누더라도 대상별로 별개의 처방을 만들어 붙이지 않는다. 사용자 방식이 각각의 상황에 어떻게 적용되는지 보여준다. 작은 회사·1인 사업에도 어떤 관점이 필요하다고 말할 때는 적용된다는 선언에서 끝내지 않고, 그 관점이 해당 사업자의 실제 판단에 왜 필요한지 중간 이유를 설명한다.
- 문장과 문단 사이에 빠진 전제가 없는지 확인한다. 갑자기 개념을 제시하지 말고 사용자가 준 경험·질문 등 출발점에서 자연스럽게 이어지는지 검토한다. 모든 강의에 똑같은 도입 형식을 강제하지 않는다.
- 각 항목마다 기계적으로 보완 과제를 붙이지 않는다. 사용자와 논리를 논의하면서 실제로 필요한 근거·사례를 골라 넣는다.
- 강의 내용은 설계자·100M·구피디·콰디와 사용자의 실제 경험을 바탕으로 한다. BPT는 문장·문단의 논리 기능을 참고하고, 원문 내용이나 저자의 경험을 치환해 복제하지 않는다. 정확한 대응 여부는 대본 제작 규칙에 따라 기록한다.

## 4. 근거·사례·자료 색인

- 사용자가 지정한 두 노션 페이지의 이피알마케팅 유튜브 롱폼 대본은 이세란의 개인 스토리가 필요할 때, 또는 강의의 주장·설명을 뒷받침할 논리적 근거가 필요할 때 찾아 활용한다. 대본에 담긴 경험·생각·판단 이유·설명 논리를 해당 내용과 연결한다. 원문과 영상 매칭을 보존하고, 실제 읽은 본문 범위에서 활용하며 원문의 조건과 의미를 유지한다. 원천·접근·매칭 상태는 [롱폼 보관목록](_원문/이세란_유튜브롱폼/00_보관목록.md)에서 확인한다.

- 마케팅 대행 부업 대상의 노션·칼럼 자료는 원문과 스토리를 보존하되, 활용본은 마케팅 대행 경험을 바탕으로 현재 B2B 강의에 쓸 관점으로 정리한다. 원문에 있는 고객사 상황·문제·판단·실행·결과를 근거로 삼고, 부업 권유나 수강생 수익화 약속을 그대로 옮기지 않는다. 실제 사건·화자·수치·조건은 바꾸지 않으며 B2B 활용 해석은 원문과 구분한다. 지정 칼럼은 글별로 빠짐없이 수집·색인하고, 개인 스토리 또는 논리적 근거가 필요할 때 찾아 쓴다. 원문·글별 활용 카드는 [이세란 스토리 보관목록](_원문/이세란_스토리/00_스토리목록.md)과 [주제별 찾기](_원문/이세란_스토리/01_주제별찾기.md)에서 확인하며, 미확보 자료는 확보된 것으로 다루지 않는다.

- 보완은 필요한 부분에만 한다. 모든 항목에 근거를 붙이거나 같은 보완 양식을 반복하지 않는다. 사용자와 논의해 근거·사례·설명·수치 확인 등 무엇이 필요한지 정한다.
- 근거가 필요한 곳에만 `*근거:`로 표시한다. 사례는 `*사례:`, 추가 설명은 `*설명:`, 사실 확인은 `*확인:` 등 해당하는 메모만 짧게 적는다. 이 표시는 필수 항목 묶음이 아니다. 충분한 내용에는 메모를 붙이지 않는다. 실제 확인한 자료와 조사할 항목은 구분한다.
- 연구는 이름만 제시하지 않는다. 무엇을 연구했고, 어떤 결과가 있으며, 해당 주장에 어디까지 쓸 수 있는지 설명한다. 조사기관 이름과 전문 지표만으로 성과를 설명하지 말고, 무엇을 비교해 어떤 결과였는지 수강생이 이해할 말로 풀어준다. 기업의 성장·철수 사례는 강의의 핵심 주장에 필요한 원인과 결과만 짧게 설명한다. 설명 요청을 기업사·계약 구조·별도 교훈까지 늘리라는 뜻으로 확대하지 않는다. 상세 근거는 조사 기록에 보존하고 본문은 사용자가 강조한 결론으로 바로 연결한다. 국가별 차이를 다룰 때는 해당 시장·운영 주체·시점을 구분한다. 시대별 회사 사례는 같은 시기에 성장했다는 이유만으로 고르지 않고, 바로 앞에서 설명한 고객 행동과 사업 방식의 변화를 보여주는지 확인한다. 사례의 결과가 설명하려는 고객의 선택·판단 변화와 다르면 유명세나 성장 규모만으로 채택하지 않는다. 사용자가 공통 비교 축을 지정한 경우 각 구간의 끝과 전체 정리를 그 축으로 맞추되, 서로 다른 변화를 억지로 같은 의미나 일직선의 발전 단계로 만들지 않는다. 구간을 나누는 기준 자체도 같은 관점인지 확인한다. 시대를 요약할 때는 여러 시대에 공통으로 나타나는 심리·행동을 그 시대만의 특징으로 잡지 않고, 이전과 달리 새로 등장한 수단·가능한 방식을 기준으로 설명한다. 등장과 대중화는 구분하며 확인 없이 역사상 최초라고 단정하지 않는다. 시대별 설명은 새로 가능해진 핵심 특징을 앞세우고, 이전 시대 및 현재와의 차이→고객 행동에 미친 영향→당시 큰 회사와 작은 회사의 마케팅 방식으로 이어간다. 뒤 시대에서 설명할 세부 조건이나 행동을 앞 시대의 대표 예시에 미리 넣어 차이를 흐리지 않는다. 대표 예시는 변화의 초점을 보여주는 것이며, 당시 다른 행동이 불가능했다는 단정으로 확대하지 않는다. 본문에서는 “키워드는 ~다”를 따로 선언하기보다 “이 시대를 한마디로 말하면”처럼 시대 설명에 자연스럽게 이어 쓴다. 고객이 믿고 선택하는 이유, 콘텐츠 형식, 노출·추천 방식처럼 서로 다른 기준을 동등한 단계로 나눈 뒤 끝 문장만 맞추지 않는다. 변화 비교는 같은 대상·상황을 이어서 무엇이 이전보다 더 구체화되거나 달라졌는지 보이게 설명한다. 각 구간에서는 먼저 무엇이 달라졌는지 고객의 실제 행동을 짧고 쉬운 말로 설명하고, 그다음 같은 대상의 구체적인 예시를 붙인다. “대중적인 인지도와 유명인의 이미지를 선택의 근거로 삼는다” 같은 추상적인 해설 대신 “유명한 사람이 써서 쓴다”, “내가 찾아보면서 비교한다”, “후기를 보며 검증한다”처럼 쓴다. 예시만으로 변화 설명을 대신하지 않는다. 짧게 정리한 고객 행동 문구는 의미와 말투의 기준이지 본문에 그대로 넣어야 하는 고정 문장이 아니다. 원래 뜻을 유지하면서 앞뒤 내용이 자연스럽게 이어지도록 표현·문장 순서·필요한 연결 설명을 조정한다. “고객 입장에서는” 같은 표지를 붙여 요약 문장을 따로 끼워 넣는 것으로 연결을 대신하지 않는다. 같은 관점의 문장을 나열하는 것만으로 변화의 방향을 설명했다고 보지 않는다. 고객 입장의 변화를 묻는 질문에는 고객의 선택 기준·행동 변화로 직접 답하고, 사업자가 고객을 이해하는 방식으로 관점을 바꿔 대신 답하지 않는다.
- 실제 사례 요청에는 구체적인 사례로 답한다. 일반 이론이나 추가 조사 필요 문구로 사례를 찾은 것처럼 대신하지 않는다.
- 확인되지 않은 경험·수치·기업가치·시점·초과달성률을 만들지 않는다. 큰 금액은 해당 시점의 확인된 소득·가격 등과 비교해 체감할 수 있게 설명하고, 비교 연도·단위와 매출·이익의 차이를 유지한다. 근거가 부족하면 사용자 주장의 의미를 임의로 바꾸지 말고 한계를 따로 논의한다.
- 그래프는 실측 자료·연구 모델 재구성·가상 예시를 구분하고 출처와 축을 표시한다.
- 전체 과정에 필요한 자료는 기존 원문을 확인해 배정한다. 확정 후 표에는 내용과 출처 ID·파일·장·페이지·문단 등 색인을 남겨 직원이 추적할 수 있게 한다.

## 5. 문서 구성과 번호

- 챕터 안에서 강별 MD 파일로 나누고 각 강의 파일을 해당 강의의 편집 기준으로 둔다. 챕터 문서는 목표·강의 연결·강별 파일 링크를 담는다. 원본 전체와 상세 연구 기록은 별도 보존하고 링크한다.
- 챕터 목표 → 목표와 강의의 연결 → 강별 개요 링크 → 원본·자료 순서로 정리한다. 목표와 강의 표는 앞에서 정한 목표 번호에 명시적으로 대응시킨다.
- 각 강의에는 중요 메시지·연결 목표와 사용자 내용을 정리한 본문을 둔다. 필요한 근거 표시는 본문 가까이에 둔다. 워크시트나 다음 강의 연결은 필요한 내용을 해당 위치에 반영하며 반복 설명을 늘리지 않는다.
- 큰 항목은 `1.`, 하위 제목은 `1-1.`, 본문 논리 단위는 `1)`, `2)`로 쓴다. 논리에 따라 문장을 더 나눌 수 있다. `1-1-1` 같은 과도한 세부 번호는 쓰지 않는다. 인트로·세대별 설명·정리·마무리처럼 내용이 나뉘는 지점에는 큰 항목 제목을 붙이고, 각 항목 안의 모든 본문 문단에 `1)`, `2)` 번호를 빠짐없이 매긴다. 문단 번호는 큰 항목마다 `1)`부터 다시 시작한다. 근거·검토 메모와 자료 링크는 본문 문단 번호에서 제외한다. 번호·구조 정리 요청만으로 문장을 바꾸거나 내용을 삭제하지 않는다.
- 강의 번호는 `1강`으로 쓴다. 개별 파일 제목 예: `# 1강. 매출 강의가 아니라 영업이익 강의`. 같은 제목에 번호를 중복해서 붙이지 않는다.
- `##` 제목 앞에 빈 줄을 한 줄 더 둔다. 문장마다 줄을 추가하라는 뜻이 아니다.
- HTML 접기·앵커 태그, 불필요한 표 번호, 중복 원문·요약, 작업 과정 해설을 본문에 늘어놓지 않는다.

## 6. 지속 갱신

- 공동 작업 시 모든 작성 규칙과 수정된 내용을 참여자들이 함께 확인하고 공유할 수 있게 한다. 공유 플랫폼과 동기화 방식은 아직 논의 중이며, 특정 도구 도입이나 이전이 확정된 것으로 처리하지 않는다.

- 매 사용자 발언에서 이후 작업에도 적용할 기준·교정·금지사항·진행 방식을 확인한다. 별도의 저장 요청을 기다리지 않고 해당 답변을 마치기 전에 관련 작성 규칙을 갱신한다. 개요와 대본에 공통이면 두 문서에 반영한다. 같은 기준은 중복 추가하지 않고 기존 항목을 수정하며, 사용자 말의 범위를 임의로 넓히지 않는다. 특정 강의 내용과 개별 할 일은 각각 해당 강의 기록과 작업 상태에 남긴다.

- 새로 지시한 개요 기준은 이 문서에, 공통 말투·내용·대본 기준은 대본 제작 규칙에도 반영한다. 중복 문구를 쌓기보다 기존 항목을 수정하고 서로 모순되지 않는지 확인한다.
- 강의에만 해당하는 새 내용은 해당 챕터와 사용자 원본 기록에 남긴다. 논의 중 제안을 확정으로 표시하지 않는다.
- 약속한 조사·그래프·색인·BPT 검증은 [작업 약속과 상태](08_작업약속과상태.md)에서 실제 완료 범위와 남은 일을 구분한다.

- 전체 개요 목록과 개별 강의 개요에 촬영 담당을 명시한다. 기존 강사 배정의 출처·기준일을 확인하고, 미배정이나 제안은 기존 배정과 구분한다.
