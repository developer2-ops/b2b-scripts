# 4-4. 구매 유도·마감 문구 (변경안)

**촬영 담당:** 권기동

상태: 사용자 검토용 내용 개요 v1. 대본·최종 승인 전.

## 강의의 역할

구매 이유와 실제 마감 조건을 명확히 전달한다.

## 반드시 다룰 내용과 개념 관계

1. 고객이 결정하는 데 필요한 구매 조건·제공 범위·다음 행동을 명확히 한다.
2. 실제 마감이나 수량 제한이 있다면 그 이유와 적용 조건을 전달한다.
3. 구매를 망설이는 이유에 답하되 증명할 수 없는 보장과 가짜 긴급성을 넣지 않는다.

위 항목들은 이번 강의에서 확보할 내용의 범위다. 각 항목의 개념·이유·조건을 충분히 설명하고 서로의 관계를 드러내야 한다. 실제 대사 순서는 후속 논리 설계에서 정하며, 모든 강의를 동일한 도입·문제·해결 공식에 맞추지 않는다.

## 수강생이 남길 결과물

구매·마감 문구

## 다룰 범위와 넘길 범위

전체 런칭·웨비나 대본으로 확장하지 않는다.

## 앞뒤 강의 연결

- 이전: **4-3 단계별 문구 — 신규·관심·구매 검토 (변경안)**의 `단계별 문구`를 필요에 맞게 참조한다. 이미 설명한 내용은 짧게 회상하고 이번 강의의 판단으로 확장한다.
- 다음: **4-5 미구매·휴면 고객 재발송 문구 (변경안)**에서는 `미구매·휴면의 이유에 맞춰 다른 정보나 제안을 보낸다.` 현재 강의의 `구매·마감 문구` 중 필요한 내용을 다음 작업의 입력으로 넘긴다.
- 챕터가 해결하는 문제: 고객 상태에 맞춰 필요한 정보와 구매 제안을 전달한다.
- 챕터 이후 연결: 메시지를 받은 고객이 확인하고 행동할 홈과 구매 경로를 연결한다.

## 직원에게 전달할 보완 작업

- 사용자에게 받을 자료·구체화할 대상: **확정된 가격·기간·수량·보장 조건·구매 질문**.
- 각 필수 설명을 원문과 대조해 충분한 설명을 작성한다. 빠진 전제나 원문과 다른 주장이 있으면 위치와 수정안을 표시한다.
- 사례는 상황·문제·판단·실행·결과·적용 한계를 정리한다. 실제 기록이 없는 숫자나 장면은 가상 예시로 명시한다.
- 추가 자료는 어느 설명을 왜 보완하는지 기록하고 기존 자료와 충돌하면 양쪽 조건을 비교한다.
- 사용자가 최종 대본으로 옮기기 쉽도록 설명 단위마다 원천 ID·장·페이지·문단을 붙인다. 개요를 바꾸는 제안과 세부 설명 보완을 구분한다.

## 이번 개요의 미확정 사항

- 기존 점검: 시트 제목이 변경안·확정 전
- BPT: 내용 순서에 대한 개요이며 특정 BPT 문장·문단 대응은 미확정이다. 최종 대본 수정 단계에서 원문 구간과 논리 기능을 검토한다.
- 시트 비고 원문: 변경안(확정 전): 상담 내용 제외, CRM 문구 포맷 설명

- 문장과 문단마다 앞의 어떤 이해를 받아 다음 내용을 말하는가? 중간 전제와 답하지 않은 질문은 없는가?
- BPT 직접 대응이 어려운 부분은 어떤 기준으로 구성했는가? 확인하지 않은 패턴을 BPT 규칙이라고 쓰지 않았는가?
- 말로 읽는 문장, 화면·슬라이드 지시, 출처 메모를 구분했는가? 촬영 때 읽을 대사에 직원용 메모가 섞이지 않는가?
